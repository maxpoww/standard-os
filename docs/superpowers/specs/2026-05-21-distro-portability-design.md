# Distro Portability — Design Spec

**Date:** 2026-05-21
**Status:** Approved, ready for implementation plan
**Related:** `2026-05-21-unlocked-keyring-design.md` (the keyring module is one of several files this spec relocates and parameterizes)

## Goal

Make this NixOS config installable on any fresh PC by editing **one line** — the username. Eliminate every hardcoded `/home/max/` reference. Move the user-owned distro source tree out of `$HOME` so end users of the distro cannot tamper with it.

## Non-goals

- Building the installer ISO that writes the initial config to a new PC. That's a separate downstream project.
- Seeding `/etc/nixos/home/` on a fresh install — the installer will do that, not this spec.
- Making Hyprland workspace-switch scripts (`~/.config/hypr/scripts/N.sh`) Nix-managed. Pre-existing Layer 3 leak, separate cleanup.
- Replacing `STDOS.nix` (per-host file). Per-host config is correctly per-host — different machines genuinely need different files.

## Architecture: the 3-layer model

The NixOS-on-this-machine setup has three layers. This spec doesn't change the layers; it changes WHERE Layer 2 lives so the user can't reach it.

```
Layer 1 — system   →  /etc/nixos/configuration.nix + /etc/nixos/modules/
                       (root-owned, kernel/services/users)

Layer 2 — home     →  /etc/nixos/home.nix + /etc/nixos/home/         ← MOVED HERE
                       (root-owned, home-manager modules — per-user
                        session config, declaratively managed)

Layer 3 — runtime  →  ~/.config/hypr/, ~/.config/waybar/, etc.
                       (GENERATED by `nixos-rebuild switch` from Layers 1+2)
```

End users of the distro interact only with Layer 3 (their running session) and `nix-env`/`home.packages` for installing programs. Layers 1 and 2 are root-owned and locked away in `/etc/nixos/`.

## Design

### 1. Move the tree

Move `/home/max/focus/` → `/etc/nixos/home/`. The entire tree, including:

| Subdir / file | Role | Moves with the rest? |
|---|---|---|
| `modules/` | home-manager modules | ✅ |
| `hosts/` | per-host config (e.g. STDOS.nix) | ✅ |
| `hypr/` | hyprland config fragments referenced by `hyprland-config.nix` | ✅ |
| `scripts/` | bash daemons (hypr-edge-bg, hypr-activities, etc.) | ✅ |
| `waybar/` | waybar config | ✅ |
| `models/` | (whisper models or similar) | ✅ |
| `tests/` | dev-only test scaffolds | ✅ |
| `docs/` | dev-only design docs (including THIS spec) | ✅ |
| `.claude/` | Claude Code project config — moves with the source tree so future maintainers get the same tooling | ✅ |
| `distro-todo.md` | dev notes | ✅ |

After the move, `/home/max/focus/` no longer exists.

### 2. Parameterize the username

Single `let` block at the top of `/etc/nixos/configuration.nix`:

```nix
{ config, lib, pkgs, ... }:

let
  primaryUser = "max";              # ← THE only line a new install edits
  userHome    = "/home/${primaryUser}";
in
{
  imports = [ ... ];

  # Propagate to all system modules
  _module.args = { inherit primaryUser userHome; };

  # Propagate to all home-manager modules
  home-manager = {
    useGlobalPkgs       = true;
    useUserPackages     = true;
    backupFileExtension = "hm-bak";
    extraSpecialArgs    = { inherit primaryUser userHome; };
    users.${primaryUser} = import ./home.nix;
  };

  # ... rest of config uses ${userHome}/... wherever it previously had /home/max/...
}
```

`_module.args` is the idiomatic NixOS pattern for making `let`-bound values available to every imported system module without threading them by hand. `home-manager.extraSpecialArgs` is the home-manager equivalent for the user side.

No `distroRoot` variable is needed — once the tree lives in `/etc/nixos/home/`, all imports inside `home.nix` use relative paths.

| File | Edits |

**Edit ordering:** all the "post-move" file edits (`/etc/nixos/home/modules/keyring-unlocked.nix`, `/etc/nixos/home/modules/hyprland-config.nix`) happen AFTER the move in step 1 — the paths in the table reflect the post-move locations.

### 4. Hyprland binds: why `~` instead of `${userHome}`

The Hyprland binds in `configuration.nix` (lines 113–136) are written into a `Binds.conf` file by `pkgs.writeText`. Two options:

- **`${userHome}/...`** — Nix interpolates at build time. The resulting file contains the literal expanded path. Works.
- **`~/...`** — Hyprland expands `~` at runtime when it parses the bind. Already used on lines 100–105 (`~/.config/hypr/scripts/volume.sh up`).

We pick `~/...` for consistency with the existing volume/brightness binds AND because it's one fewer interpolation hop. The activation scripts that `install` files still need `${userHome}` because shell `install` doesn't reliably expand `~` in all contexts.

## Verification

After all moves and edits:

1. **Parse-check each modified file:**
   ```bash
   for f in /etc/nixos/configuration.nix /etc/nixos/home.nix \
            /etc/nixos/modules/users.nix /etc/nixos/modules/nautilus-system.nix \
            /etc/nixos/home/modules/keyring-unlocked.nix \
            /etc/nixos/home/modules/hyprland-config.nix; do
     nix-instantiate --parse "$f" > /dev/null && echo "OK: $f"
   done
   ```
   Expected: every file prints `OK: …`, no parse errors.

2. **Eval-check the full system:**
   ```bash
   sudo nixos-rebuild dry-build 2>&1 | tail -40
   ```
   Expected: exits 0, no `error:` lines. Common failures:
   - `error: getting status of '/home/max/focus/...': No such file` → an import wasn't updated to `./home/...`.
   - `error: function 'anonymous lambda' called without required argument 'primaryUser'` → `extraSpecialArgs` or `_module.args` not wired.

3. **Apply:**
   ```bash
   sudo nixos-rebuild switch 2>&1 | tail -60
   ```
   Expected: exits 0, `activation finished`.

4. **Functional sanity:**
   - Keyring still auto-unlocks: re-run yesterday's Task 4 Step 6 (`secret-tool` roundtrip with no GUI prompt).
   - Hyprland binds still work: try `Super+1` through `Super+9` (workspace switch) and `Super+E` (kitty).
   - Chrome still no-prompt: `pgrep -af google-chrome | grep -- '--password-store=basic'`.
   - User account intact: `id max` shows the same UID/groups as before.

## Risk and rollback

- **Risk: import path miss.** A missed `/home/max/focus/...` reference would fail at eval. Caught by `dry-build` before `switch`. Mitigation: ordering — do moves first, then edit imports, then dry-build, then switch.
- **Risk: `_module.args` collision.** Unlikely — the variable names `primaryUser`/`userHome` aren't used elsewhere in the codebase. If a collision surfaces, rename to `cfg.distro.primaryUser`.
- **Risk: stale references inside moved modules.** Comments inside `hyprland-config.nix` reference the old path; the file `keyring-unlocked.nix` likely doesn't. Surveyed: only `hyprland-config.nix` and the README-style `distro-todo.md` are affected. All updated as part of file edits.
- **Rollback:** moves are `mv`, reversible. If switch breaks, `sudo mv /etc/nixos/home /home/max/focus`, restore the unedited `home.nix`/`configuration.nix` from `*.bak` (which we keep until the new layout is verified), `sudo nixos-rebuild switch`.

## What this enables next

After this spec lands, a distro installer can:

1. Ask the new user for their desired username.
2. Write `/etc/nixos/` from the ISO, substituting `primaryUser = "<entered-username>"` in `configuration.nix`.
3. Run `nixos-rebuild switch`.

That's the full first-boot install flow. No second knob, no per-user seed step in `$HOME`, no path edits.
